# Self security review: F06/F07 provisional foundation, W01, W02 and the example world

Date: 2026-11-15. Reviewer: the implementing assistant session (self review; **not** an independent review).

## Trust boundaries considered

1. **Untrusted world documents** (`@browser-vr-engine/world`): prototype-polluting keys (`__proto__`, `constructor`, `prototype`) are rejected before any field is read; entity/prefab/asset counts, hierarchy depth, prefab nesting, component bytes, identifier length and coordinates are bounded; parent cycles, prefab cycles and unresolved parent/prefab/asset references fail validation. External asset URIs and `..`/absolute paths are rejected — remote content must go through the asset pipeline (A25). `parseWorld` caps input at 32 MiB. Result: no blocker.
2. **Runtime authorization** (`@browser-vr-engine/runtime`): local mode loads only `origin: local` worlds when `world:load:local` is granted; remote worlds additionally need `world:load:remote` and an explicit trusted id. Absent capabilities deny. Persistence/transport throw without their capability. Transport clones messages (no shared mutable state). Result: no blocker.
3. **Renderer adapter**: component data is clamped numerically; only a fixed set of primitives and data-only behaviours (`spin`, `bob`, `orbit`) exist; no creator code executes (W17/W18 own that). Failed or aborted mounts release partial resources.
4. **Static site**: strict CSP (`default-src 'self'`, no inline script, `wasm-unsafe-eval` only), no cookies, no third-party origins, no secrets. localStorage stores only the last world id. Audio starts only after a user gesture. The docs Markdown renderer escapes all HTML and drops non-http(s) links (tested).
5. **Supply chain**: exact pins with sha512 integrity from the public registry; `check:dependencies` audit passed; Babylon Apache-2.0 notices ship as `THIRD_PARTY_NOTICES.txt`.

## Findings

- Bundle size (~6.9 MiB minified) is a performance, not security, issue; tree-shaken deep imports are follow-up work (W19/W22).
- Render serves the example over HTTPS; WebXR requires a secure context, which that satisfies.

No blocking finding.
